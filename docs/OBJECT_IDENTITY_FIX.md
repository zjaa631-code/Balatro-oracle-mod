# 0.13.4 私有卡牌身份与误停修复

## 日志依据

本次 HTS25CEP 底注 2 的日志显示两种补充包以及冥王星使用结果 MATCH，随后 consumable:c_fool MISMATCH。愚者预期生成冥王星，实际记录却把 sort_id=80 的旧天文学家小丑认作变成冥王星。RNG、金钱、手牌等级及牌组投影没有差异。

Card:init 分配 G.sort_id，Card:load 恢复卡牌保存的 sort_id。恢复的编号并不保证与随后新建对象的编号不重复。验证器曾把所有 Joker、扑克牌与消耗牌塞入以 sort_id 为键的同一个表，因而新冥王星覆盖旧小丑记录，产生虚假的“改牌”结果，并触发全局预测保护。牌堆的直接读取页面不经过这个预测开关，所以仍然可用。

## 修复

- 消耗牌快照与验证使用 Oracle 模块内私有弱引用表，为不同真实对象分配不同的数字身份。同一对象跨快照保持身份。
- 手牌选择、目标排除、生成／删除／变化比较，以及牌组验证对齐均使用此私有身份。
- 原版 sort_id 和 playing_card 原样保留；sort_id 继续负责原版 RNG 候选排序和生成先后排序。不能用私有编号替换随机候选排序。
- 身份表不挂到任何游戏对象上、不保存到存档、不放入 shadow state；快照中只有数字身份，没有真实卡牌引用。
- 重复牌面不合并；真实生成内容、版本、永久加成、牌序或 RNG 差异仍触发 MISMATCH，未关闭保护。

此修复进一步替换 0.13.2 的 sort_id 验证身份对齐。原版移除卡牌导致 playing_card 重新编号的回归继续保留。

## 测试

新增 12 seeds × 7 类生成牌场景，在已有 Joker／扑克牌与新生成卡之间设置原版编号碰撞，并执行当前安装的原版 use_consumeable／create_card；验证 MATCH 且共用预测开关保持可用。另覆盖力量／隐秘的选牌、安卡／妖法的随机目标，以及生成 key／edition／RNG 篡改的故障检出。

完整回归 136 组 PASS，包含 1,378 个消耗牌原版使用场景及全部既有商店、标签、补充包、快捷预览、Joker、牌组、Boss 与钩子回归。代码哈希与环境见 object-identity-regression-report.txt，输出见 object-identity-regression-results.txt。

不操作真实牌局。更新后重启游戏继续原存档，由玩家实机验收。
