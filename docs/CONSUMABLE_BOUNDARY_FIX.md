# 0.15.2 消耗牌验证边界修复

用户报告撤销后标签预测不可用。实机日志显示：撤销读档前，愚者生成水星的预期结果被拿来与水星已用掉、对子从 12 级升到 13 级的状态比较。该条记录的 RNG 和牌组投影没有差异，差异在生成牌已不在库存和后一次使用造成的牌型升级。验证器将其记为 MISMATCH，停用了当前会话的预测。撤销不会盲目清除这个错误标记，因此界面随后继续显示不可用。

原因是验证使用非阻塞事件，等待使用锁解除。当原版已允许下一次输入、验证事件尚未执行时，下一张牌可以先改变状态，导致上一个动作验证得太晚。

## 修复

- 保存待验证事务，在下一次使用、买卖、重掷、出牌、弃牌、切换盲注、兑现、离开商店或跳过补充包之前，先验证已解除使用锁的事务。
- 验证仅读取真实结果，不调用真实 RNG 或重新执行消耗牌。每个事务只记录一次，旧事件再次执行时直接结束。
- 撤销时重置事务代次，取消旧回调。旧局的事件即使再次被调用，也不会与恢复后的牌局比较。
- 保留真实 MISMATCH 停用保护，不通过无条件清空错误标记来掩盖偏差。
- 维持 0.15.1 的补充包撤销过渡修复。未更改 RNG 算法或全局存档。

## 验证

新增 12 个 seed 的“愚者生成水星 → 验证事件延迟 → 立即使用水星”回归，使用本机实际原版消耗牌逻辑。愚者只比较生成结果，水星只比较对子升级，各记录一次 MATCH，预测开关保持可用。

另测旧回调在撤销重置后退出、不重复记录，以及确实丢失生成牌时仍记录 MISMATCH 并停用预测。完整图形环境和其他模组的组合仍需实机复验。

旧会话已经误停时，安装更新并重启游戏即可清除运行时标记；不必删除存档或撤销历史。
