# 当前牌局撤销 — 0.15.0

## 使用

- F9：撤销上一次已记录的操作；可重复按键回退多个节点。恢复期间按键不会重复执行。
- 预知 → 撤销：显示可用节点数量、上一个节点的底注／回合／金钱，以及撤销按钮。
- 失败后，在离开本局、开始新局前按 F9 恢复。开始新局后不会跨局撤销。
- 动画、重掷、开包过渡或读档尚未结束时，提示等待；结束后再次操作。
- 正常退出后继续同一牌局，可以读取已经落盘的历史。安装前的动作没有历史，无法倒推。
- 原有 F8 与局内左下角按钮保留；暂停菜单没有预知按钮，返回直接回到游戏。

## 范围

撤销记录原版保存内容：G.GAME（包含逐 key RNG）、扑克牌与各 CardArea 的牌序、手牌、弃牌、小丑、消耗牌、商店、标签、盲注与牌背。补充原版读档没有完整恢复的全局扑克牌顺序、选中状态、排序计数及被削弱小丑持有标记。

在出牌、弃牌、购买、出售、使用消耗牌、开包、商店／Boss 重掷、选盲注、跳过盲注、离开商店及兑现前建立节点。Hook 内部的强制弃牌属于同次出牌，不另建节点。监听原版保存以跟踪更新后的牌局；同次操作的多次异步保存合并，不把动画中间态当作独立操作。

原版不序列化正在打开的补充包，因此开包及包内选牌／使用属于一个整体操作；撤销返回开包前。不是包内逐张回退。对于兑现，保存结算完成后的金额，恢复时使用原版兑现按钮显示该金额，不重新触发奖励、投资标签或全局统计；该恢复画面只显示兑现总额，不重播收入明细。

不回退账号进度、解锁、成就或生涯统计。撤销历史不保存这些数据，也不会用旧节点覆盖它们。实际重玩后的原版统计仍会照常累计。主菜单设置、更换存档档位、删除存档与开始另一局不属于当前牌局撤销范围。没有重做功能；撤销后新的操作形成新路线。

## 存储与恢复

模块：`undo/history.lua` 管理节点及索引，`undo/storage.lua` 管理校验和压缩，`undo/runtime.lua` 挂接原版保存／加载生命周期，`ui/undo.lua` 提供原版页面及 F9。

历史在 LÖVE 存档目录下的 `oracle-undo/<档位>/<牌局标识>/` 中。每个节点独立压缩并使用 SHA-256 校验，两个交替索引允许最近索引损坏时退回前一个完整索引。校验失败的节点不会执行恢复。文件读取使用隔离 Lua 环境。写入失败停用当前撤销并报告，不拦截原版正常操作。

历史没有固定步数上限。旧节点及旧局文件不会自动删除，因此长期使用会占用磁盘空间；无需历史时可在关闭游戏后手动清理 `oracle-undo` 文件夹。不要删除原版的 `save.jkr` 或档案文件。

恢复走原版事件队列和 `start_run(savetext)` 读档；恢复存档请求交给原版 FIFO 保存线程，避免直接写 `save.jkr` 与旧保存请求竞争。清理旧局事件与预测缓存，恢复期间锁定操作和预测，并抑制中间保存；完成后保存稳定状态。快照移除 `ACTION`，避免原版继续游戏的开包动作在撤销时自动重播；真实原版存档仍保留该字段。

## 验证与边界

自动测试使用本机 Balatro 1.0.1o-FULL、Steamodded 26.829.0、Lovely 0.9.0 的实际代码和 LuaJIT 2.0.5：

- 100 次操作的节点独立性、连续撤销、新路线、RNG 还原。
- 磁盘重读、档位及新局隔离、索引回退、损坏节点与写入失败。
- 11 类动作边界，原版序列化和返回值保持。
- 动画期间多次保存合并，操作稳定后结束事务，后续原版独立保存仍可建立撤销节点。
- 原版重启调度回调、旧事件清理、恢复锁、FIFO 请求及预测缓存重建。
- 普通继续游戏不把新存档映射到旧局实体；同局历史接续。
- 开包 ACTION、整包事务、失败状态可撤销。
- 已完成结算恢复总额，避免再次运行奖励和全局统计。
- F9 与原版页面按钮的可用条件。
- 原版 Card / CardArea 保存与加载，25 组共 1300 张牌的牌序、版本、贴纸、蜡封、朝向和价格回读。
- 本机 LÖVE DLL 的实际压缩、解压、散列接口和损坏检测。

这些是自动化单元／集成测试。完整 `Game:start_run` 的图形对象构建在测试中使用替身，原版重启回调、序列化与 Card/Area 读写使用实际源码；不能据此声称完整实机加载已验收。界面布局、读档动画及操作后的完整牌局仍需实机验证，因此界面明确标记 Experimental。

建议实机依次检查购买后 F9、重掷后 F9 再重掷是否相同、出牌／弃牌回退、整包回退、兑现前后、失败后恢复及退出继续后的历史；同时确认已有商店／标签／悬浮预测仍可用。
